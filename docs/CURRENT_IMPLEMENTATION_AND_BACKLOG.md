## 2. 역할과 권한의 현재 DB 흐름

| 역할 | 기본 데이터 | 가능한 범위 | 권한 변경 주체 |
|---|---|---|---|
| 일반회원 | `users.role=CONSUMER` | 카탈로그, 장바구니, 주문, 배송지, 고객 문의 | 최고관리자 또는 판매자 승인·해지 업무 흐름 |
| 판매자 | `users.role=SELLER`, 판매점 연결 | 일반회원 기능 + 본인 판매점 운영, 응찰, 이행, 구독 상태 | 판매자 심사 승인·해지 업무 흐름 |
| 일반관리자 | `users.role=ADMIN`, `admin_level=STANDARD` | `user_feature_permissions`에서 ON인 관리자 기능만 메뉴·REST CRUD 접근 | 최고관리자 |
| 최고관리자 | `users.role=ADMIN`, `admin_level=HIGHEST` | 전체 관리자 기능, 일반관리자 부여·해지, 기능 토글 | 최고관리자 본인만 유지 |

> 일반관리자 권한 변경은 `user_feature_permissions`에 현재값을 저장하고 `permission_audit_logs`에 남긴다. 일반관리자 부여·해지는 `administrator_role_audit_logs`에 별도로 기록한다.

| 우선순위 | 항목 | 남은 범위 | 완료 조건 |

| P0 출시 차단 | 판매자 지급·정산 운영 | PG 중개 정산 또는 지급대행 계약 연동, 정산 가능 전환, 지급 실패·재시도·대사 | 플랫폼 자금 흐름과 판매자 지급 이력이 자동 대사된다. |
| P0 출시 차단 | 외부 운영 보안 | 운영 RLS 회귀, Storage 정책, 서비스 키 범위, 비밀값·도메인·CORS 점검 | 익명·일반 JWT의 직접 DB·비공개 파일 우회가 차단된다. |
| P0 출시 차단 | 운영 관측성·백업 | 오류 추적, 구조화 로그, DB 백업·복구, 배포 롤백, 장애 알림 | 실패한 주문·결제·매칭을 운영자가 탐지·복구할 수 있다. |
| P1 핵심 보완 | 판매자 구독 해지 | 판매자 본인 해지 API/UI, 즉시/만료일 해지 정책, 이력·등급 정규화 | 판매자가 신청·상태 조회·해지를 모두 수행하고 관리자가 이력을 조회한다. |
| P1 핵심 보완 | 일반관리자 권한 회귀 E2E | 최고관리자 부여→일반관리자 메뉴/API 허용→해지→즉시 차단 시나리오 | 실제 브라우저 역할별 자동 회귀가 통과한다. |
| P1 핵심 보완 | 인증 E2E | 이메일·Google·Kakao의 메인·직접 관리자·콜백 경로 역할 동기화 테스트 | 로그인 성공 뒤 잘못된 로그인·권한 없음 화면이 재현되지 않는다. |
| P1 핵심 보완 | NTS 사업자 진위확인 | 사업자번호 조회 어댑터, 실패 재시도, 수동 심사 대체 경로 | 판매자 심사에서 자동 확인 또는 명시적 수동 검토가 작동한다. |
| P1 핵심 보완 | 알림 채널화 | 저장 알림을 이메일·푸시·SMS 중 선택 채널로 발송하고 실패 이력 저장 | 주문·응찰·결제·클레임·문의 주요 상태가 수신자에게 전달된다. |
| P2 확장 | Redis·실시간 | 다중 인스턴스 락, 지연 제안, Realtime/푸시 구독 | 수평 확장 환경에서도 낙찰 1인·가용 슬롯 불변식이 유지된다. |
| P2 확장 | 법정·거래 문서 | 결정적 템플릿 기반 견적서·거래명세서·영수증·세금계산서 생성 | 주문 데이터와 동일한 문서가 권한별로 내려받기 가능하다. |
| P2 확장 | 접근성·모바일·부하 QA | 키보드·스크린리더·반응형·동시 응찰·피크 부하 E2E | 출시 기준 시나리오와 성능 목표를 통과한다. |
| P3 제품 확장 | 철수야 오피스·철수의 수리 | 기존 계정·판매자·구독 기반의 별도 세션과 도메인 모델 | 핵심 철물 주문 흐름을 침범하지 않는 독립 도메인 계약이 완성된다. |

## 5. 다음 개발 순서

| 순서 | 작업 묶음 | 선행 조건 | 결과물 |
|---|---|---|---|
| 1 | 판매자 구독 해지와 관리자 권한·인증 E2E | 현재 V39, 최신 API 실행 | 해지 상태 전이·권한 부여/회수·직접 로그인 회귀 시나리오 |
| 2 | NTS·알림 채널 운영 연결 | 환경변수·발송 계정·운영 정책 | 판매자 심사 자동화와 핵심 이벤트 전달 |
| 3 | PG·환불·정산 지급대행 설계·연동 | PG사 계약, 수수료·지급 정책, 법률 검토 | 승인·웹훅·대사·지급 흐름 |
| 4 | 보안·관측성·백업·출시 QA | 운영 인프라와 배포 환경 | RLS/Storage 검증, 알림, 복구, E2E·부하 보고 |
| 5 | Redis·Realtime와 신규 세션 확장 | 핵심 주문·결제 출시 기준 충족 | 수평 확장 매칭, 오피스·수리 도메인 분리 |
