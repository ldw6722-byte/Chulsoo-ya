## 3. 설계·구현 경계

| 구분 | 현재 구현 가능 | 구현 금지·보류 |
|---|---|---|
| 주문·매칭 | 상태 전이, 0/30/60초 단계, 슬롯·락·재입찰·패널티 이력·개발 승인 | PG 승인 완료를 전제로 한 실제 자금 이동 |
| 정산·환불 | 수수료·정산·HOLD·환불 요청·관리자 개발 승인·감사 이력 | 카드 취소·부분 환불·계좌 송금·PG 웹훅 |
| 구독 | 관리자 상품 CRUD, 판매자 신청·상태·해지·개발 승인 | 정기 결제·자동 갱신·실제 결제 영수증 |
| NTS·알림 | 어댑터 계약, 수동 심사, 인앱 알림·읽음·이력·재시도 설계 | 실제 NTS 키 호출, SMS/알림톡/푸시 운영 발송 |
| 오피스·수리 | 세션·상태·스키마·REST 계약·모의 E2E 설계 | 기존 철물 도메인에 섞는 구현, 토큰 실결제 |

## 4. 설계 후 다음 구현 묶음

1. **P0 인증·권한 E2E:** 최고·일반 관리자, 판매자, 일반회원의 로그인·OAuth 콜백·권한 부여/해지·직접 API 차단.
2. **P0 판매자 구독 해지:** 판매자 본인 해지, 등급·만료·이력, 관리자 강제 등급과의 표시·상태 계약.
3. **P0 매칭 회귀:** 가용 슬롯·단일 낙찰·0/30/60초·5분/2분·재입찰·패널티의 테스트 증거.
4. **P1 알림·운영 예외:** 인앱 알림·읽음·배송 불가·미응찰 안내·NTS 어댑터/수동 심사.
5. **P2 확장 세션:** 오피스 이후 수리. 각 세션은 철물 주문·결제 도메인과 혼합하지 않는다.
6. **P3 출시 준비:** 관측성·백업·복구·부하·접근성·개인정보 보존.
7. **P4 PG 최종 통합:** PG·환불·웹훅·지급대행/에스크로·계약·법무·세무 준비가 동시에 충족된 뒤 시작.
