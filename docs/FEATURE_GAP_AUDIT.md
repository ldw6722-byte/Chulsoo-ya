> **보관 문서:** 이 문서는 V1~V6 중심의 2026-08-13 초기 갭 감사 기록이다. 판매자 신청·증빙, 환불·정산, 클레임 HOLD, 쿠폰, 관리자 운영, 카카오 연동, RLS, 판매점 운영 정보, 일반관리자 세부 권한 등은 이후 구현됐다. 현재 완료·보완·미구현 판단은 `CURRENT_IMPLEMENTATION_AND_BACKLOG.md`를 사용한다.

## 감사 결론

현재 프로젝트는 **카탈로그·장바구니·기본 주문 생성·매칭·판매자 운영 화면·관리자 주문/매장/후기/고객지원 화면**까지 구현되어 있다. 그러나 **판매자 가입 검증, 실결제와 환불, 클레임·정산 HOLD, 법정 서류, 쿠폰, 플랫폼 단위 알림, 관리자 재무 운영**은 아직 전부 또는 핵심 일부가 빠져 있다.

> 상태 전이·금액·가용 슬롯·역할 판정은 백엔드와 PostgreSQL이 결정하며, 프론트엔드는 서버 확정 결과만 렌더링한다.

## 검증된 중요 제약

| 제약 | 적용 기준 |
| :--- | :--- |
| 매칭 시간 | 서버 기준 5분 매칭, 2분 판매자 물품 확인 |
| 낙찰 | 주문 단위 잠금과 `bids`의 낙찰자 유니크 인덱스로 판매자 1인만 확정 |
| 결제 순서 | 판매자 확인 완료 뒤 `PAYMENT_PENDING`에서만 결제 가능 |
| 클레임 | 생성 트랜잭션에서 관련 정산을 반드시 `HOLD`로 변경하고 이력을 남김 |
| 서류 | AI 없이 고정 템플릿에 DB 값을 주입해 생성 |
| 민감정보 | DB 비밀번호, service role, PG·NTS 키는 환경변수/배포 비밀 저장소에만 보관 |

## 구현 순서

1. **판매자 온보딩과 검증**: 신청 데이터·증빙 파일 메타데이터·승인 상태부터 비파괴 마이그레이션과 테스트로 구축한다.
2. **기존 매칭 검증 및 패널티 이력 보강**: 실제 주문-응찰-확인-이행을 역할별로 검증하고, 자동 제한을 불변 이력으로 남긴다.
3. **결제·취소·환불**: 개발 스텁을 Toss 어댑터 계약으로 교체하기 전, 내부 상태·멱등성·환불 이력부터 완성한다.
4. **클레임·정산·증빙**: 소비자 접수, 판매자 처리, 관리자 중재, 정산 HOLD를 하나의 트랜잭션 경계로 구현한다.
5. **서류·쿠폰·플랫폼 알림·관리자 재무**: 앞선 확정 상태를 입력으로 결정적 생성과 운영 도구를 연결한다.
6. **외부 설정과 출시 점검**: OAuth/SMTP/Kakao/Toss/NTS/Storage의 실제 비밀 설정, Realtime, 권한·접근성·회귀 테스트를 마무리한다.

## 이번 감사에서 제외한 항목

상품 실제 이미지는 사용자 지시에 따라 별도 작업으로 보류한다. Google·Kakao OAuth, SMTP, Toss, NTS의 공급자 비밀 설정은 코드만으로 완료할 수 없으므로 각 기능 구현 후 필요한 대시보드 설정값을 별도로 확인한다.
