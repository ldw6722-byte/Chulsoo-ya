# 결제 취소·환불 계약

## 권한과 처리 경계

| 행위 | 권한 | 주문 상태 | 결제 상태 | 결과 |
| :--- | :--- | :--- | :--- | :--- |
| 결제 전 취소 | 주문자 | `WAITING_MATCH`, `MATCHED`, `SELLER_CONFIRMING`, `PAYMENT_PENDING` | 결제 없음 | 주문 `CANCELLED`, 낙찰 슬롯 해제 |
| 결제 직후 취소 | 주문자 | `PAID` | `PAID` | 전액 취소 이력, 결제 `CANCELLED`, 주문 `CANCELLED`, 슬롯 해제 |
| 전액 환불 | 관리자 | `PAID` | `PAID` | 환불 이력, 결제 `REFUNDED`, 주문 `CANCELLED` |
| 부분 환불 | 관리자 | `PAID`, `PREPARING` | `PAID` 또는 `PARTIAL_REFUNDED` | 환불 이력, 잔액 차감, 결제 `PARTIAL_REFUNDED` |
| 배송 이후 분쟁 | 주문자·판매자·관리자 | `DELIVERY_IN_PROGRESS`, `COMPLETED` | 모든 결제 상태 | 직접 환불 금지, 클레임 단계에서 정산 HOLD 후 처리 |

## V10 스키마

```sql
create table refunds (
    id bigint generated by default as identity primary key,
    payment_id bigint not null references payments(id),
    order_id bigint not null references orders(id),
    refund_type varchar(20) not null,
    amount integer not null check (amount > 0),
    reason varchar(500) not null,
    idempotency_key varchar(100) not null unique,
    status varchar(20) not null,
    requested_by_user_id bigint not null references users(id),
    processed_by_user_id bigint references users(id),
    pg_cancel_key varchar(120),
    pg_response_message varchar(500),
    created_at timestamptz not null,
    completed_at timestamptz,
    version bigint,
    constraint ck_refunds_type check (refund_type in ('CANCEL', 'REFUND')),
    constraint ck_refunds_status check (status in ('REQUESTED', 'SUCCEEDED', 'FAILED'))
);
create index ix_refunds_payment_created on refunds(payment_id, created_at desc);
```

`payments.remaining_amount`는 다음 불변식을 만족한다.

```text
0 <= remaining_amount <= amount
amount = sum(succeeded refund.amount) + remaining_amount
```

## REST 계약

| API | 호출자 | 설명 |
| :--- | :--- | :--- |
| `POST /api/orders/{orderId}/cancel` | 주문자 | 결제 전 취소 또는 `PAID` 직후 전액 취소. `Idempotency-Key` 헤더 필수인 결제 취소 경로는 서버가 기존 결과를 재사용한다. |
| `GET /api/orders/{orderId}/payment` | 주문자·관리자 | 결제 금액·잔액·상태·환불 이력 조회 |
| `POST /api/admin/payments/{paymentId}/refunds` | 관리자 | 전액/부분 환불. `amount`, `reason`, `idempotencyKey` 필수. |

## TDD 조건

1. 같은 취소/환불 멱등성 키는 두 번째 환불 이력과 잔액 차감을 만들지 않는다.
2. 부분 환불은 남은 결제 금액을 초과할 수 없다.
3. 부분 환불 뒤 잔액이 0이면 결제 상태는 `REFUNDED`가 된다.
4. 결제 전 주문 취소는 환불 이력을 만들지 않는다.
5. `PAID` 주문의 소비자 취소는 결제 취소 이력·결제 상태·주문 상태를 한 트랜잭션으로 함께 변경한다.
6. 배송 시작 이후에는 직접 취소/환불을 거부하고 클레임 경로를 요구한다.
7. 환불 이력에는 요청자·처리자·사유·PG 응답 키·처리 시각이 남는다.

## 외부 PG 경계

현재 PG 승인과 취소는 개발용 결정적 스텁 키를 기록한다. 운영에서는 서버 전용 PG 어댑터가 승인/취소 API와 서명 검증 웹훅을 수행하며, 브라우저에 PG 비밀값을 전달하지 않는다.
