# 클레임·정산 HOLD 계약

## 상태 전이

| 현재 | 행위자 | 이벤트 | 다음 | 정산 |
| :--- | :--- | :--- | :--- | :--- |
| 없음 | 소비자 | 반품·교환·부분 교체 요청 | `REQUESTED` | 즉시 `HOLD` |
| `REQUESTED` | 판매자 | 접수 확인 | `SELLER_REVIEWING` | `HOLD` 유지 |
| `REQUESTED`, `SELLER_REVIEWING` | 판매자 | 회수 지시 | `PICKUP_SCHEDULED` | `HOLD` 유지 |
| `REQUESTED`, `SELLER_REVIEWING` | 판매자 | 재발송 등록 | `REPLACEMENT_SHIPPING` | `HOLD` 유지 |
| 판매자 처리 상태 | 관리자 | 중재·환불 확정 | `RESOLVED` | 전액 환불이면 종료, 부분 환불이면 잔액 기준 유지 |
| 판매자 처리 상태 | 관리자 | 기각 | `REJECTED` | `RELEASABLE` |
| 판매자 처리 상태 | 소비자·관리자 | 분쟁 확대 | `ESCALATED` | `HOLD` 유지 |

## V11 스키마

```sql
create table settlements (
    id bigint generated by default as identity primary key,
    order_id bigint not null unique references orders(id),
    store_id bigint not null references stores(id),
    payment_id bigint references payments(id),
    gross_amount integer not null check (gross_amount >= 0),
    status varchar(20) not null,
    hold_reason varchar(500),
    held_at timestamptz,
    released_at timestamptz,
    created_at timestamptz not null,
    updated_at timestamptz not null,
    version bigint,
    constraint ck_settlement_status check (status in ('PENDING', 'HOLD', 'RELEASABLE', 'SETTLED'))
);

create table claims (
    id bigint generated by default as identity primary key,
    order_id bigint not null references orders(id),
    consumer_id bigint not null references users(id),
    store_id bigint not null references stores(id),
    claim_type varchar(30) not null,
    reason_code varchar(50) not null,
    description varchar(2000) not null,
    status varchar(30) not null,
    created_at timestamptz not null,
    updated_at timestamptz not null,
    resolved_at timestamptz,
    version bigint,
    constraint ck_claim_type check (claim_type in ('RETURN', 'EXCHANGE', 'PARTIAL_REPLACEMENT')),
    constraint ck_claim_status check (status in ('REQUESTED', 'SELLER_REVIEWING', 'PICKUP_SCHEDULED', 'REPLACEMENT_SHIPPING', 'ESCALATED', 'RESOLVED', 'REJECTED'))
);
create unique index ux_claims_active_order on claims(order_id) where status not in ('RESOLVED', 'REJECTED');

create table claim_evidences (
    id bigint generated by default as identity primary key,
    claim_id bigint not null references claims(id) on delete cascade,
    object_key varchar(300) not null unique,
    content_type varchar(100) not null,
    byte_size bigint not null check (byte_size > 0),
    created_at timestamptz not null
);
create table claim_events (
    id bigint generated by default as identity primary key,
    claim_id bigint not null references claims(id) on delete cascade,
    event_type varchar(50) not null,
    actor_user_id bigint references users(id),
    actor_role varchar(30) not null,
    detail varchar(2000) not null,
    created_at timestamptz not null
);
```

## REST

| API | 권한 | 핵심 입력 | 결과 |
| :--- | :--- | :--- | :--- |
| `POST /api/orders/{orderId}/claims` | 주문자 | type, reasonCode, description | 클레임 생성·정산 `HOLD`·불변 이벤트 |
| `POST /api/claims/{claimId}/evidences` | 요청자 | 이미지/영상 파일 | 비공개 저장소 키·증빙 메타데이터 |
| `GET /api/claims/{claimId}` | 요청자·해당 판매자·관리자 | — | 클레임·증빙·이벤트·정산 상태 |
| `GET /api/seller/claims` | 낙찰 판매자 | — | 판매자 처리 큐 |
| `POST /api/seller/claims/{claimId}/actions` | 낙찰 판매자 | action, note, trackingNumber | 판매자 확인·회수·교환·거절 상태 전이 |
| `GET /api/admin/claims` | 관리자 | status 선택 | 운영 큐 |
| `POST /api/admin/claims/{claimId}/resolve` | 관리자 | decision, note, refundAmount | 중재 결정·정산 상태·결정적 문서 |

## 필수 불변조건

1. 클레임 생성과 정산 `HOLD`·`CLAIM_REQUESTED` 이벤트는 하나의 트랜잭션이다.
2. 활성 클레임은 주문당 하나이며, 판매자는 자신의 낙찰 주문만 처리한다.
3. 판매자·관리자 상태 전이는 서버 서비스 계층에서만 허용한다.
4. 증빙 파일은 허용 MIME·시그니처·용량 검증 후 UUID 객체 키로 비공개 저장소에 기록한다.
5. 환불은 관리자 결정에서만 기존 `PaymentRefundService`를 통해 실행하고, 판매자 화면은 환불을 확정하지 않는다.
6. 문서는 AI 생성이 아닌 클레임·주문·결정 DB 값을 결정적 템플릿에 주입해 생성한다.
