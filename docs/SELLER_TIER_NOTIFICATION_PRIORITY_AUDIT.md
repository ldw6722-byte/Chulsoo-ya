# 판매자 등급별 주문 공개 우선순위 감사

> **기준일:** 2026-08-22  
> **범위:** 철물 O2O 세션의 판매자 구독 등급, 최대 슬롯, 주문 제안 공개 단계 및 판매자 설정 화면. 수리·오피스 확장 세션의 독립 정책은 현재 철물 화면에 적용하지 않는다.

## 1. 단일 기준 정책

`README.ko.md`와 `docs/PLANNING_ALIGNMENT_REGISTER.md`가 현재 제품 규칙의 우선 문서다. 두 문서는 같은 등급·슬롯·시간 정책을 명시한다.

| 판매자 등급 | DB 상태 의미 | 최대 슬롯 | 주문 제안 공개 시각 | 화면 표기 원칙 |
| :--- | :--- | :---: | :--- | :--- |
| `PREMIUM` | 유효한 프리미엄 구독 | 15 | 주문 생성 후 0초부터 | `즉시 공개 대상` |
| `GOLD` | 유효한 골드 구독 | 8 | 주문 생성 후 30초부터 | `30초 후 공개 대상` |
| `SILVER` | 비구독 기본 등급 또는 만료 후 기본 등급 | 3 | 주문 생성 후 60초부터 | `60초 후 공개 대상` |

> **기준 규칙:** 0~30초는 프리미엄, 30~60초는 프리미엄·골드, 60초 이후에는 프리미엄·골드·실버에 주문 제안을 공개한다. 비구독 판매자는 실버로 취급한다.

동일 시점에 상위 등급의 **수신 가능한 판매점이 전혀 없으면**, 서버는 가용 슬롯·영업 상태·패널티를 확인한 뒤 하위 등급으로 더 일찍 확산할 수 있다. 이는 특정 주문을 불필요하게 지연시키지 않기 위한 서버의 예외 경로이며, 판매자 설정 화면의 고정 문구로 계산하거나 보장해서는 안 된다.

## 3. 현재 구현 대조

| 계층 | 확인 결과 | 판정 |
| :--- | :--- | :--- |
| DB 판매점 상태 | 판매점은 `tier`, `tier_slot_cap`, 구독 만료 시각, 설정·예약·진행 슬롯을 보관한다. 구독 만료 스케줄러는 실버 기본 등급으로 정규화하고 이력을 저장한다. | DB 상태 기준 존재 |
| 서버 매칭 | `OfferDispatchService`는 판매점 DB의 `tier`, 신뢰 점수, 가용 슬롯, 주문 수신, 패널티를 확인한다. `SubscriptionTier`의 현재 공개 지연은 프리미엄 0초·골드 30초·실버 60초다. | 실제 매칭은 서버가 판정 |
| 판매자 API | `SellerStore`는 현재 `tier`와 `tierSlotCap`을 반환한다. | 화면이 서버 상태를 받을 수 있음 |
| 관리자 구독 관리 | 관리자 구독 서비스는 DB 판매점의 등급·만료일·이력을 변경하고, 판매자에게 인앱 알림을 남긴다. | 관리자→DB→판매자 연동 존재 |
| 판매자 설정 화면 | 과거 타입 `FREE/STANDARD/PREMIUM`의 `tierLabel`과 0/3/6초 분기 문구를 사용한다. 현재 `SILVER/GOLD/PREMIUM` 서버 계약과 불일치한다. | **즉시 수정 필요** |
| 관리자 계정 이메일 상태 | 현재 판매자 구독 응답에는 계정 이메일·승인 상태가 포함되지 않으며, 관리자 계정 이메일 상태와 구독은 별도 계약이다. | 단일 운영 뷰가 필요하면 API 확장 필요 |

## 5. 구현 원칙

판매자 화면은 **DB에서 계산된 현재 구독 상태와 슬롯 한도**만 보여야 한다. 주문 공개 시각은 정책상 기준 시각을 설명할 수 있으나, 현재 주문에서 실제로 언제 제안을 받을지 보장하는 값처럼 표시하면 안 된다. 상위 등급 판매점이 수신 불가하면 서버가 하위 등급으로 조기 확산할 수 있기 때문이다.

관리자 대시보드는 등급 변경·구독 만료·이메일 기반 관리자 승인·기능 토글을 모두 DB 변경과 감사 이력으로 처리해야 한다. 프론트는 이를 Axios REST 응답으로 렌더링할 뿐, 등급·슬롯·우선순위·관리자 승인 여부를 자체 계산하거나 하드코딩하지 않는다.

## 6. 다음 구현 순서

1. 클라이언트 타입과 레이블을 `SILVER/GOLD/PREMIUM`으로 통일하고, 판매자 설정의 과거 0/3/6초 UI를 제거한다.
2. 기존 DB 구독 상태 API를 판매자 설정과 관리자 구독 패널이 공통으로 사용하도록 대조한다.
3. 최고관리자가 **정책 수치 자체**를 바꿔야 하는 요구가 확정되면, Java enum 상수를 직접 편집하는 대신 정책 테이블·마이그레이션·감사 이력·관리자 CRUD를 추가한다.
4. 관리자 운영 요약에 계정 이메일, 관리자 승인·근무 상태, 판매점 ID, 구독 등급·만료일·슬롯을 결합한 읽기 전용 조회를 추가한다.
